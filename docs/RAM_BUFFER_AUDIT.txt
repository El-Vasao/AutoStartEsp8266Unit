RAM / buffer audit (ESP8266, AutoStartEsp8266Unit)
==================================================

Protocol-required (staging or wire):
  - MqttFsmClient: TX/RX fixed arrays for one MQTT wire frame each (cannot stream away).
  - lwIP + ESPAsyncTCP: socket buffers managed by SDK / library.
  - GSMController: UART ring char[] (fixed, no heap String).

Streaming already (no full JSON in RAM):
  - Config/program POST: body chunks written to LittleFS tmp (WebServer.JsonIngest).
  - MQTT status publish: encoded via Print into TX budget (measure + send).
  - SSE UI status: JSON built via Print into a contiguous line buffer (application framing).

Purged PoolManager slot:
  - WebSsePayload: moved to translation-unit static in WebServer.Runtime.cpp so only
    the web layer owns the SSE line buffer; same BSS size as before (SSE_STATUS_JSON_MAX).

Tunable library macro (build_flags):
  - SSE_MAX_QUEUED_MESSAGES: caps per-client SSE queue depth in ESPAsyncWebServer (ESP8266).
    Set to 16 so one incremental SSE tick + several `log` lines stay under the hard discard threshold; was 4 and caused async_ws overflow on connect.

HTTP POST config/program:
  - Limit HttpPostJson::MAX_BYTES = Limits::CONFIG_JSON_SIZE (4096): protocol cap only.
  - Body is streamed chunk-by-chunk to LittleFS tmp; no second full 4K RAM copy in this path.

Optional future work (not done here):
  - Shrink JsonBytes::Web::SSE_STATUS_JSON_MAX only after logging shows stable headroom.
  - AsyncEventSource::send builds a temporary String per message in the library; cannot fix
    app-side without forking ESPAsyncWebServer.

Operational decisions (2026-05):
  - AP startup now prefers minimal station cap in setup/emergency mode to increase headroom
    before first TCP accept.
  - `/bootstrap` is guarded by low-heap checks and can return `LOW_MEMORY` under pressure
    instead of forcing a large stream allocation and crashing.
  - SSE/log send path is guarded by heap/maxBlock thresholds in addition to queue depth.
  - Full async-stack replacement is deferred behind SLO gate (see docs/RAM_STABILIZATION_PLAYBOOK.md).
