# `common`: Logger и устойчивость hot-path

## Logger (SSE-only)
Файлы:
- `include/common/Logger.h`
- `src/common/Logger.Core.cpp`

Политика:
- Логи идут в UI через SSE (UART0 занят GSM).
- На ESP8266 форматирование/доставка логов не бесплатны, поэтому действует **throttling**:
  - короткие bursts разрешены
  - при перегрузке лишние сообщения **дропаются**
  - периодически отправляется summary вида: `[Logger] throttling: dropped=N`

Цель: **лучше потерять часть логов, чем повесить цикл или поймать WDT** при активной UI-сессии и GSM churn.

# `common`: константы, буферы, логирование, утилиты

## `Constants.h`
Единая точка лимитов:
- размеры строк (`TextBytes::*`)
- лимиты JSON (`JsonBytes::*`)
- тайминги (`Timing::*`)
- лимиты SSE очередей (`WebSseLimits::*`)
- FS/OTA лимиты

Идея: на ESP8266 лимиты — часть архитектуры, их нельзя “подкрутить где-то локально”, не оценив эффект.

## `PoolManager`
Фиксированные слоты под JSON и bytes, чтобы:
- web/config/fs не конкурировали за heap
- избежать фрагментации и случайных `DynamicJsonDocument`

Правило: если модуль формирует JSON для API/SSE/MQTT — он должен брать slot из `PoolManager`.

## `Logger`
Централизованный вывод:
- форматирование в фиксированный буфер
- доставка в UI через SSE (без хранения истории на устройстве)

## `Utils`
CRC, таймеры, безопасные helper’ы без динамики.
